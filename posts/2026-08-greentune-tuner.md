# 造一个「绿色」调音器:零依赖、2 MB,从吉他到古筝 12 种乐器

我学过一点点吉他,也喜欢一些乐队和它们的歌。算不上专业音乐人,只是想有个趁手的小工具:想调音的时候能调音,想练节奏的时候能打拍子——就这么简单。

市面上很多调音器要付费、带广告,这其实无可厚非——软件也要养活自己,那些付费的进阶功能也确实做得很强大,该有的它们都有。只是对我来说,最基本的「调音」和「打节拍」,原理其实很简单。所以我想做的不是加法,而是一道**减法**:不堆功能,就做一个小小的东西——**不占地方,也不让人烦躁**,点开就能用。

于是有了 **GreenTune**:一个**完全免费、不依赖任何第三方库**的调音器 + 节拍器,iPhone / iPad / Mac / Apple Watch 都能用。我一直觉得音乐是无国界的,所以尽量把它做得人人可用:内置 24 种语言、App 内一键切换。角落里放了一个**可选打赏**按钮,纯自愿,点不点都不影响使用。这篇记一下几个我觉得有意思的实现。

## 一、全程零依赖,所以它只有 2 MB

一条铁律:**不引任何第三方库**,声音和画面能自己算就自己算。

- 基频检测是自写的 **YIN 算法**;
- 节拍器的"哒"声是**程序化合成**的(一段正弦 + 指数衰减包络),没有一个音频素材;
- 表盘、指针是 SwiftUI 画的;连 App 图标都是一个 CoreGraphics 脚本现生成的。

结果是整个 App **真机安装 ≈ 1.5–2 MB**(`otool -L` 里除了系统框架什么都没有)。附带好处:全程离线,没有任何数据离开设备。

## 二、调音的核心:YIN + 一个「防乱跳」状态机

调音器最烦人的体验,是你拨一下弦,指针在好几根弦之间疯狂跳——因为拨弦的**衰减尾音**里泛音很强,基频检测会一会儿认成 E、一会儿认成它的八度。

我给自动判弦加了个小状态机,规则很朴素:

- **确认即锁定**:认出某根弦后,就以它为当前目标;
- **抗泛音/尾音**:偏离当前弦超过 ±250 音分的读数(八度泛音、别的弦余音都在这窗外)先当作可疑,**要连续 3 帧**都指向同一根新弦,才真的换弦,否则画面冻住不动;
- **调准后自动解锁**:当前弦稳定进 ±5 音分(表盘变绿)约 8 帧后自动松开,你拨下一根弦立刻就能识别。

再叠一层 EMA 平滑指针。改完之后,拨弦时指针稳稳停在该在的地方,不再抽搐。

## 三、三个 SwiftUI 把我坑到的地方

### 坑 1:`@Published` 的 `didSet` 里给自己赋值 = 秒崩

节拍器改拍号时 App 直接闪退。崩溃日志写着 `EXC_BAD_ACCESS · Thread stack size exceeded due to excessive recursion`——栈溢出。

我原本图省事,在属性里做钳位:

```swift
@Published var beatsPerBar: Int = 4 {
    didSet { beatsPerBar = min(max(beatsPerBar, 1), 12) }   // 💥
}
```

普通存储属性在自己的 `didSet` 里再赋值**不会**重新触发观察者,所以这写法平时没事。但 `@Published` 是个属性包装器,它把属性变成了 computed——**在 `didSet` 里赋值会再走一遍 setter,又触发 `didSet`**,无限套娃直到栈爆。

修法:只有**真的越界**才回写,钳好的值等于自身就不再赋值,递归立刻收敛:

```swift
didSet {
    let clamped = min(max(beatsPerBar, 1), 12)
    if beatsPerBar != clamped { beatsPerBar = clamped; return }
    syncAccentPattern()
}
```

> 顺带一个排查技巧:模拟器里 App「总是重启」,大概率是**崩溃循环**(启动即崩→被拉起→再崩),不是别的程序在改它。去 `~/Library/Logs/DiagnosticReports/` 翻 `.ips` 崩溃报告,看时间是不是一分钟崩好几次,就能确诊。

### 坑 2:菜单总也点不中,原来是被自己刷新冲掉的

乐器/调弦选择器一开始用原生嵌套 `Menu`。结果吉他子菜单里的「Standard」等项**几乎点不中**——手指还没落下,菜单就被弹回重建了。

原因是调音引擎**每一帧**都在更新 `@Published`(频率、音分、当前弦),整个页面的 `body` 跟着高频重建,把已经弹出的 `Menu`(尤其子菜单)不断重置。

两招解决:

1. 把 `Menu` 换成 `Button` + `.popover(isPresented:)`——popover 只认那个绑定的布尔值,`body` 再怎么重建都不会被弹回;
2. **打开选择器时顺手把音频读数暂停**(冻结那些 `@Published`),关闭时再恢复并重新吸附。

> 教训:需要长时间交互的浮层,别挂在一个被高频刷新的 `body` 上。

### 坑 3:底部按钮被标签栏吃掉

节拍器展开「加速练习」后控件变多,底部的「开始」按钮被 Tab 栏盖住了。原因是我用固定 `VStack` + `Spacer` 撑高度,内容一旦超屏,既不滚动、也不给标签栏安全区让位,就直接溢出被覆盖。

改成:标题栏钉顶,其余控件放进 `ScrollView`(`.scrollBounceBehavior(.basedOnSize)`——装得下不回弹、超屏才滚),底部再加一段保护 padding。凡是控件可能变多的页面,都该这样兜底。

## 四、从吉他到古筝:顺手做成全品类弦乐器

既然引擎是"检测频率 → 吸附到最近的目标音",那目标音换成什么乐器的空弦都行。于是把「调弦」抽象成「**乐器 → 调弦**」两级目录,一口气加了 **12 种乐器**:吉他、贝斯、尤克里里、曼陀林、班卓、小/中/大提琴,以及 **琵琶、古筝、二胡、古琴**。

弦数从 2(二胡)到 21(古筝)。古筝那 21 根显然不能手敲频率,写了个生成器:D 大调五声(D E F# A B)从 D2 往上铺 21 根到 D6。UI 上少弦用左右分列,古筝这种就换成横向滚动的弦条。

为了不抄错一堆频率,还写了个「科学音名 ↔ MIDI ↔ 频率」的小换算器,`"E2"` 进去、`82.41 Hz` 出来。

## 五、24 种语言,App 内一键切换

本地化也坚持零依赖:语言字符串直接写在代码里,用一个 `ObservableObject` 管当前语言,切换瞬间重渲染、**不重启、离线可用**。默认跟随系统,也能在地球图标里手动切 24 种语言中的任意一种。

这些语言全部内置一共才 ~140 KB——有人问能不能"按需下载省空间",在 iOS 上不划算:系统的 App 瘦身只按设备(架构/分辨率)裁剪、**不按语言**;而这点体积拆出来做按需下载,收益 ~0.1 MB,还会毁掉"即点即换、离线可用"。留着最舒服。

## 六、iPad 与 Mac 大屏:不砍功能,把同一套东西重新排一遍

在 iPad 上跑起来才发现:App 只是把 iPhone 的**单列窄版**居中摆着,节拍器页锁死在 520pt 宽、还顶着屏幕上沿,下面一大片空白——横向空间全浪费了。

我不想为 iPad 做"减配版",也不想照搬手机版拉大。目标很简单:**同一套功能,按大屏重新排布**。

关键是选一个干净的"这是不是大画布"信号。我没有用设备型号(`UIDevice.idiom`),而是用 **`horizontalSizeClass`**:

- iPad 全屏(横竖屏)水平尺寸类都是 `.regular` → 走新的**双列布局**;
- iPhone、以及 iPad **分屏 / Slide Over** 变窄时是 `.compact` → 自动回落到原来的单列手机版。

这样"窗口变窄就退回手机版"是免费送的,符合直觉。

布局本身零重写——原来那些子视图(BPM、节拍点、滑杆、拍号、练习卡片……)早就是各自独立的计算属性,只是把 `body` 按尺寸类分成两支:

```swift
@Environment(\.horizontalSizeClass) private var hSize

var body: some View {
    GeometryReader { geo in
        if hSize == .regular { regularLayout(geo: geo) }  // iPad 双列
        else                 { compactLayout(geo: geo) }  // iPhone 原样
    }
}
```

iPad 版把控件分成两列:**左边演奏区**(大 BPM、节拍点、速度滑杆、±/打拍、开始),**右边设置/练习区**(拍号、细分、加速/减速练习)。

一个小细节值得记:双列内容通常不占满一屏,如果顶对齐,底部又会留一大块空白——回到原点。解法是给内容套一层 `.frame(minHeight: 可用高度, alignment: .center)`:**内容短就垂直居中,内容长(练习卡片展开)就正常滚动**,两头都不难看。调音器那边则顺手把表盘上限从 420 放大到 520,大屏上更醒目。

不过这一版留了两个尾巴。一是 iPhone Pro Max/Plus **横屏**(此时也是 `.regular`)会跟着用双列;二是搬到 **Mac 上,双列压根没出现**——窗口拉多宽,还是窄窄一条单列居中。

翻下去才想起来:`horizontalSizeClass` 是 UIKit 的东西,**只在 iOS 下编译**,macOS 上根本没有这个环境值,我那句 `hSize == .regular` 在 Mac 上恒为 `false`——所以 Mac 永远拿不到双列。

修法是把"这是不是大画布"的判据从**尺寸类**换成**实际宽度**。好在两个页面的 `body` 本来就包在 `GeometryReader` 里,宽度各平台都拿得到:

```swift
// horizontalSizeClass 在 macOS 不可用;GeometryReader 宽度各平台都有。
// 宽画布 = 够宽放两列 且 不是 iPhone(手机任何方向都保持单列)。
private func isWideCanvas(_ width: CGFloat) -> Bool {
    #if os(iOS)
    if UIDevice.current.userInterfaceIdiom == .phone { return false }
    #endif
    return width >= 700
}
```

一个 `width >= 700` 的阈值,顺手把两个尾巴一起收了:iPad mini 竖屏 744pt 起步全都 ≥700(等价于原来的 `.regular`)、iPad 分屏变窄(~500 / ~320)自动回落单列;Mac 窗口够宽就双列、拖窄了干净地塌回单列;而 iPhone 就算横屏超过 700,也被那句 `idiom == .phone` 守卫挡在门外——原来"手机横屏被迫双列"的那点别扭,反而随手消失了。**一处判据,iPad 和 Mac 一起解锁。**

同一版里也把**调音器**页补上了同样的双列:左边大表盘 + 音名,右边是调弦选择器和弦列表(半音阶没有弦表,就居中单列;古筝这种多弦换成横向弦条)。至此调音器和节拍器在大屏上观感统一。

同一套改动我同步到了各条线(主线 iOS/iPad、watchOS 分支、以及拍号进阶分支),让大屏适配在 iPhone / iPad / Mac 上保持一致。

## 七、把同一套引擎搬上手表

既然核心是「纯逻辑 + 纯 SwiftUI」,那手腕上也该能用。于是加了一个**随 iPhone 安装的 Apple Watch 伴侣 App**(watchOS 11 起),同样是调音器 + 节拍器两页。

最舒服的地方是:**逻辑层一行没改**。YIN 检测、调音状态机、节拍器引擎、音名换算、24 种语言——这些本来就是不带任何 UIKit / AppKit 依赖的纯 Swift 文件,直接**原样编进** watch target 就能跑。表端只需要新写「小屏能看清」的紧凑 UI:一个大音名 + 居中的 ±50 音分横条(调准了变绿),节拍器则是数字表冠(Digital Crown)转 BPM、一个大大的 Start/Stop。

真正需要为手表重新想的,是**怎么打拍子**。手表扬声器又小又容易被袖子捂住,光靠"哒哒"声在练习时基本听不清。所以节拍器在表上改成**触觉打拍**——用 `WKInterfaceDevice` 的 Taptic 引擎,让节奏直接敲在手腕上:

- 强拍一记较沉的**单击**(`.start`)、
- 普通拍一记轻点(`.click`)、
- 静音拍不振。

这里有个细节是戴上表才发现的:强拍一开始用的是 `.notification`——它其实是**一串多段长震动**,敲下去"拖沓",跟清脆的一声对不齐;而且我把震动扔到主线程去播,主线程正忙着画圆点动画时,震动就**慢半拍还发抖**。改成两者都用单击、并且**直接在音频排程的那个线程上触发震动**(这个方法本就可以任意线程调用),让"响"和"震"落在同一个时间点,手感立刻跟上了。

戴着表、手搭在琴上就能跟节奏,不用盯屏幕。

戴上表用了几天,又顺手补了几处小而关键的打磨:

- **调音时清楚显示"第几根弦"**。标准吉他最粗和最细都是 E,只显示个字母根本分不清是第 6 弦还是第 1 弦;所以在音名下方加了一行醒目的大字「第6弦 / String 6」,拨哪根一目了然。
- **切页不再卡死**。表上调音器要占麦克风(录音会话)、节拍器要出声(播放会话),两个会话在同一块小设备上"抢方向盘"就会卡。改成**任意时刻只有当前那一页持有音频**:切到调音页才开麦、切走立刻交还;打开 App 默认停在节拍器页,不主动碰麦克风(也就不会莫名其妙弹权限)。
- **熄屏就干净地停下**。之前锁屏后,声音被系统冻住、可打拍的定时器还在跑,就成了"只震不响"的僵尸;现在一旦熄屏/切走就整体停止,回来重新点开始——手表这一版本就是「前台练习」的定位,不去后台常驻耗电。

一处诚实的限制先记下:系统会对触觉**合并 / 限流**,BPM 拉很高(大概 >180)时可能丢拍,而且只在 App **前台**可靠——所以这一版把它定位成「前台练习用」,后台长时间打拍要另开 `WKExtendedRuntimeSession`,留到以后。打赏、灵动岛、古筝那 21 根弦的横向滚动条也都没往表上搬——小屏幕上做减法,才配得上"绿色纯净"这四个字。

顺带一提,加这一整个 watch target,靠的是**手写 `project.pbxproj`**(这个工程从一开始就是手写工程文件、没用 Xcode 拖拽),给新 target 用确定性的 ID 前缀避免冲突,并让「嵌入 watch app」这步只在 iOS 构建时发生——这样 macOS 版的产物里干干净净,不会莫名其妙塞进一个手表 App。

## 小结

整个 App 的哲学就一句话:**能自己算的都自己算,不引一行第三方**。换来的是 2 MB 的体积、全程离线,以及一个我自己每天调琴都在用、点开就能用的小工具。

这是个**用爱发电**的小东西。做它、写下这篇,只是希望它能帮到那些和我一样喜欢音乐的人——让更多人更容易地弹起、唱起。也私心盼着,能因此在这个世界上听到更多、更动人的作品。
